2.1. Raszteres és vektorgrafika2.1. Raster and vector graphics

Raszteres képnél minden képpont színét külön tároljuk. Ez természetes megoldás például fényképekhez. Vektorgrafikában ezzel szemben az alakzatok geometriai leírását tároljuk: egy szakasz két végpontját, egy kör középpontját és sugarát. Logók, műszaki rajzok és egyszerű ábrák esetén ez rendszerint célszerűbb.A raster image stores the colour of each pixel, which is natural for photographs. Vector graphics stores geometric descriptions instead: two endpoints for a segment, or a centre and radius for a circle. This is often convenient for logos, diagrams and technical drawings.

Ha egy kis raszterképet sokszorosára nagyítunk, a képpontok látható négyzetekké válnak, a ferde széleken pedig lépcsőhatás jelenik meg. Vektoros képnél a tárolt alakzatot új méretben is kiértékelhetjük. A képernyőn azonban végül ezt is képpontokkal jelenítjük meg: ez a raszterizálás.Enlarging a small bitmap reveals its square pixels and stepped edges. A vector shape can instead be evaluated at a new size. On screen, however, it must also be converted to pixels; this is called rasterisation.

A jó szakaszrajzoló eljárás képe közel legyen az ideális szakaszhoz, tartalmazza a végpontokat, legyen összefüggő és lehetőleg egyenletes vastagságú. Az eredmény ne függjön a végpontok megadásának sorrendjétől. Mivel egy képen sok szakaszt is megjeleníthetünk, az algoritmus sebessége sem mellékes.A useful raster line algorithm should remain close to the ideal segment, include both endpoints, and produce a connected, approximately uniform line. The result should not depend on the order of endpoints. Efficiency matters, since many segments may be drawn.

2.2. Egyszerű növekményes algoritmus2.2. Simple incremental algorithm

Legyen a szakasz két végpontja P₀ = (x₀, y₀) és P₁ = (x₁, y₁), ahol x₀ < x₁. A koordináták teljes megváltozása Δx = x₁ − x₀ és Δy = y₁ − y₀. Az egyenes meredeksége m = Δy / Δx. Ha az x-koordinátát minden lépésben eggyel növeljük, a hozzá tartozó y-koordináta m értékkel változik.Let the endpoints be P₀ = (x₀, y₀) and P₁ = (x₁, y₁), with x₀ < x₁. Define Δx = x₁ − x₀ and Δy = y₁ − y₀. The slope is m = Δy / Δx. When x increases by one, y increases by m.

m = ΔyΔx,    yi+1 = yi + m

A számított y-koordináta általában nem egész szám, ezért a megfelelő pixel kiválasztásakor kerekítünk. A módszer egyszerű, de meredek szakasznál |m| > 1: egyetlen x szerinti lépéssel több pixelsort is átléphetünk.The computed y-coordinate is usually not an integer, so it is rounded to a pixel coordinate. The method is simple, but for |m| > 1 a single x-step may skip several rows of pixels.

Például a P₀ = (0, 0) és P₁ = (3, 7) szakasznál m = 7/3. A kirajzolt pixelek (0,0), (1,2), (2,5), (3,7): a kép nem összefüggő. Függőleges szakaszra a meredekség sem számítható így.For P₀ = (0,0) and P₁ = (3,7), the slope is 7/3. The selected pixels are (0,0), (1,2), (2,5) and (3,7), leaving gaps. This slope-based form also cannot handle vertical segments.

2.3. DDA-algoritmus2.3. DDA algorithm

A DDA (Digital Differential Analyzer) az előző módszer problémáját úgy küszöböli ki, hogy mindig a nagyobb elmozdulás irányában tesz egységnyi lépéseket. Nem feltétlenül az x-koordinátát növeljük eggyel: előbb meghatározzuk a szakasz hosszabb vetületét.The DDA (Digital Differential Analyzer) avoids the previous problem by taking unit steps along the axis with the larger displacement. We do not always increment x; first we find the larger coordinate change.

n = max(|Δx|, |Δy|),    dx = Δxn,    dy = Δyn

Ekkor n > 0 esetén max(|dₓ|, |dᵧ|) = 1. A szakasz kezdőpontjától indulva minden lépésben hozzáadjuk a két növekményt az aktuális koordinátákhoz, és a kapott pontot egész koordinátákra kerekítjük. A módszer a meredek, csökkenő és függőleges szakaszokra is alkalmazható. Ha n = 0, csak egyetlen pixelt rajzolunk.For n > 0, max(|dₓ|, |dᵧ|) = 1. Starting from the first endpoint, both increments are added on each iteration and the resulting coordinates are rounded to integer pixels. This works for steep, descending and vertical segments too. When n = 0, only one pixel is drawn.

DDA szakaszrajzoló algoritmus
Bemenet:Input: S szín; x₀, y₀, x₁, y₁ egész számokcolour S; integer endpoints x₀, y₀, x₁, y₁
Δx ← x₁ − x₀;   Δy ← y₁ − y₀
n ← max(|Δx|, |Δy|)
x ← x₀;   y ← y₀
Pixel(x, y, S)
haif n = 0 akkor végethen return
dₓ ← Δx / n;   dᵧ ← Δy / n
ciklusfor i ← 1, …, n
x ← x + dₓ;   y ← y + dᵧ
Pixel(round(x), round(y), S)

A DDA minden esetben n + 1 képpontot állít elő, a két végpontot is beleszámítva. Az algoritmus egyszerű, de a valós számokkal végzett műveletek és a kerekítések miatt lehetőséget ad további egyszerűsítésre.DDA generates n + 1 pixel positions, including the endpoints. It is straightforward, but floating-point arithmetic and rounding suggest a further simplification.

2.4. Midpoint szakaszrajzoló algoritmus2.4. Midpoint line algorithm

A Midpoint-módszer minden lépésben két szomszédos pixel közül választ. Először csak a 0° és 45° közötti irányszögű szakaszokat vizsgáljuk, azaz Δx > 0 és 0 ≤ Δy ≤ Δx. Az aktuális P = (x, y) pixel után a lehetséges következő pont E = (x+1, y), illetve NE = (x+1, y+1).The Midpoint method chooses between two neighbouring pixels at each step. First consider slopes between 0° and 45°, so Δx > 0 and 0 ≤ Δy ≤ Δx. After P = (x,y), the candidates are E = (x+1,y) and NE = (x+1,y+1).

A döntéshez a két jelölt pixel közötti M = (x+1, y+½) pont helyzetét használjuk. Az egyenes implicit alakja F(x,y) = Ax + By + C = 0, ahol A = −Δy, B = Δx és C = Δy·x₀ − Δx·y₀. A választott előjelmegállapodás szerint F pozitív az egyenes fölött és negatív alatta.The decision uses the midpoint M = (x+1,y+½) between the two candidates. Write the line implicitly as F(x,y) = Ax + By + C = 0, where A = −Δy, B = Δx and C = Δy·x₀ − Δx·y₀. With this sign convention F is positive above the line and negative below it.

F(x,y) = −Δy·x + Δx·y + (Δy·x₀ − Δx·y₀)

Jelöljük d = F(x+1, y+½) értékkel a döntési változót. Ha d < 0, az ideális egyenes a középpont fölött halad, ezért NE-t választjuk. Egyébként E következik. Döntetlen esetben tehát E-t választunk.Let d = F(x+1,y+½) be the decision variable. If d < 0, the ideal line lies above the midpoint, so choose NE. Otherwise choose E. Thus ties select E.

d < 0 ⟹ NE,    d ≥ 0 ⟹ E

Nem érdemes minden lépésben újra kiszámítani F teljes értékét. Ha E-t választottuk, a következő döntési változó A = −Δy értékkel változik; NE esetén a változás A+B = Δx−Δy. A kezdőérték a P₀ pontból d₀ = −Δy + Δx/2. Mivel csak az előjel számít, minden értéket megszorozhatunk kettővel, így végig egész számokkal dolgozhatunk.There is no need to evaluate F from scratch at every step. Choosing E changes the decision value by A = −Δy, whereas NE changes it by A+B = Δx−Δy. At P₀, d₀ = −Δy + Δx/2. Since only the sign matters, multiplying all values by two yields integer arithmetic throughout.

d₀ = Δx − 2Δy;   ΔE = −2Δy;   ΔNE = 2(Δx − Δy)
Midpoint szakaszrajzoló algoritmus (0°–45°)
Bemenet:Input: S szín, két egész koordinátájú végpont, 0 ≤ Δy ≤ Δx, Δx > 0colour S, integer endpoints, 0 ≤ Δy ≤ Δx, Δx > 0
Δx ← x₁ − x₀;   Δy ← y₁ − y₀
d ← Δx − 2Δy;   x ← x₀;   y ← y₀
Pixel(x, y, S)
ciklusfor i ← 1, …, Δx
haif d < 0
y ← y + 1;   d ← d + 2(Δx − Δy)
különbenelse
d ← d − 2Δy
x ← x + 1
Pixel(x, y, S)

2.4.1. Általános szakaszrajzolás2.4.1. Segments in any direction

Az eddigi levezetésben a szakasz jobbra és legfeljebb 45°-os szögben emelkedett. Tetszőleges szakasz esetén a lépés irányát sₓ és sᵧ előjelváltozók adják meg. Ha |Δy| > |Δx|, a két koordináta szerepét felcseréljük: ekkor az y lesz a főirány. A döntési változó képlete a fő- és mellékirány hosszára változatlanul alkalmazható.The derivation assumed a segment rising to the right with slope at most one. For arbitrary directions, sign variables sₓ and sᵧ determine the step directions. When |Δy| > |Δx|, the y-axis becomes the major axis. The same decision rule applies to the major and minor displacements.

Midpoint – általános eset
Bemenet:Input: S szín, x₀, y₀, x₁, y₁ egész számokcolour S, integer endpoints
ha x₀ > x₁ vagy (x₀ = x₁ és y₀ > y₁), akkor P₀ ↔ P₁
a ← |x₁−x₀|;   b ← |y₁−y₀|
sₓ ← sgn(x₁−x₀);   sᵧ ← sgn(y₁−y₀)
csere ← (b > a);   ha csere, akkor felcserél(a, b)if swapped, swap(a, b)
d ← a − 2b;   x ← x₀;   y ← y₀
Pixel(x, y, S)
ciklusfor i ← 1, …, a
haif d < 0
ha csere: x ← x+sₓ; különben: y ← y+sᵧif swapped: x ← x+sₓ; else: y ← y+sᵧ

különbenelse
d ← d − 2b
ha csere: y ← y+sᵧ; különben: x ← x+sₓif swapped: y ← y+sᵧ; else: x ← x+sₓ

A két végpont megadásának sorrendjét a megvalósítás egységesítheti, így a döntetlen esetekben is ugyanazt a raszteres szakaszt kapjuk. Az általános változat a vízszintes, függőleges és csökkenő szakaszokra is működik.A program can canonicalise endpoint order to ensure the same pixels even in tie cases. The general form also handles horizontal, vertical and descending segments.

2.5. A három algoritmus összehasonlítása2.5. Comparing the three algorithms

A növekményes módszer x szerint lépked, ezért meredek szakasznál megszakadhat a raszteres vonal. A DDA a hosszabb vetületet választja lépésirányul, így minden sorhoz vagy oszlophoz hozzárendel egy képpontot. A Midpoint ugyanezt a célt a döntési változó egész aritmetikás frissítésével éri el.The incremental method steps along x, so steep segments can produce gaps. DDA steps along the larger coordinate displacement and therefore selects a pixel in each relevant row or column. Midpoint achieves the same goal by updating an integer decision variable.

A DDA és a Midpoint sok szakasznál azonos pixeleket választ ki. A különbség elsősorban a számításokban van; félpixeles helyzetben a kerekítés és a döntetlen eset szabálya eltérő eredményt is adhat. A következő demó mindhárom algoritmus képét ugyanazon végpontokkal jeleníti meg. A forráskód itt nem módosítható.For many segments, DDA and Midpoint select the same pixels. Their main difference is computational. At exact half-pixel positions, rounding and the tie rule can also produce different results.
